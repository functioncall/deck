# L3 Landing — Spec

> Frozen execution spec for the **L3 Landing** Ralph loop (4 epics). Grounds in
> [docs/SPEC.md](../SPEC.md) (§1 the offer, §3 IA + landing anatomy, §5 L3), the
> five [ADRs](../adr/), [agent_docs/content-model.md](../../agent_docs/content-model.md)
> (authoritative for typed content + the offer-oriented IA),
> [agent_docs/design-system.md](../../agent_docs/design-system.md), and
> [CONTEXT.md](../../CONTEXT.md) (the help-don't-sell voice + glossary). Once the
> loop runs this spec is read-only. There is no separate verify epic: the full
> build/lint/typecheck gate runs on the last epic (nav+seo), and final functional
> verification is **manual** — the user opens `/` and confirms the full sales page
> renders from typed content with working CTAs, SEO/OG, and a persistent header CTA.

---

## Context

Beontheloop is a Next.js brand + pre-sell site (see SPEC §1). L0 laid the
foundation; L1 built the bespoke design system (atoms → molecules → organisms →
`MarketingPageTemplate`, all token-only, in `/styleguide`); L2 componentized the
Deck (`/deck` slide-player) and **extracted the deck's diagrams as reusable
components** (`LLMDiagram`, `ContextWindow`, `HarnessFrame`, `Gantt` in
`src/components/diagrams/`) — explicitly so the landing page can reuse them as
marketing visuals.

L3 builds the **home / sales page only** — `/` — per the SPEC §3 anatomy, composed
from L1 organisms + L2 diagram visuals, driven by **typed content** (no copy
hard-coded in components). The voice is **help-don't-sell**, storytelling,
map→expedition (CONTEXT.md). The page assembles into `/` via the L1
`MarketingPageTemplate` (Navbar + slotted sections + Footer), adds a persistent
header "Get the Kit" CTA, and sets SEO metadata + per-route OG cards.

**Done when:** `pnpm install && pnpm lint && pnpm exec tsc --noEmit && pnpm build`
is green; `/` renders the full SPEC §3 anatomy (Hero → Problem → The Shift → Free
Deck preview → What's in the Kit → Proof → Pricing → FAQ → Final CTA) from typed
content; the persistent header "Get the Kit" CTA is present; CTAs route to the
deck (`/deck`) and to a buy target (placeholder until L4); SEO metadata + OG cards
are set.

## Locked decisions

1. **Offer-oriented, typed content** — editorial/catalog copy is typed data in
   `src/content/` (`offers.ts`, `faq.ts`, `testimonials.ts`), never hard-coded in
   components; a new offer is a new `Offer` entry, not a new page type.
   ([content-model.md](../../agent_docs/content-model.md))
2. **Compose, don't rebuild** — `/` is assembled from L1 organisms
   (`Navbar`, `Hero`, `Footer`, `Accordion`, `PricingTier`, `TestimonialCard`,
   `CTAButtonGroup`, `EmailCaptureForm`) and L2 diagram components
   (`LLMDiagram`, `ContextWindow`, `HarnessFrame`, `Gantt`) via the L1
   `MarketingPageTemplate`. **No new atoms; reuse L1 components.** ([ADR-0005](../adr/0005-bespoke-atoms-with-radix.md))
3. **Tokens only — no hard-coded design values** — every color/size resolves to a
   Tailwind utility from the L0 `@theme`; the no-hard-coded-values ESLint rule
   (scoped to `src/components/**`) is the enforcement. Section components live under
   `src/components/` (sections are organisms/composites) and obey the rule.
   ([ADR-0005](../adr/0005-bespoke-atoms-with-radix.md))
4. **Help-don't-sell voice + the glossary** — copy uses the CONTEXT.md terms exactly
   (Deck = "the map", Harness Starter Kit = the paid hero, Founding price, Screencast
   = bundled bonus, Pre-sell); the proof is the artifact + the result (the free
   Deck + the Kit's actual files, judgeable before purchase) + concrete metrics
   ("270 files / 59 min / exit 0"; 95–99% task-fit). Anonymous — no named author
   (ADR-0006). (SPEC §1, §3; CONTEXT.md)
5. **Pricing = founding $29 → $49, 30-day guarantee** — the Pricing section reflects
   the rising-price urgency (not a deadline) and the no-questions 30-day refund.
   Prices come from `offers.ts` (tunable until L4 ships). (SPEC §1; CONTEXT.md)
6. **FAQ uses the Radix Accordion** organism from L1 (keyboard-operable, ARIA correct).
7. **No server wiring in L3** — `EmailCaptureForm` is markup + client validation only
   (no POST; `/api/subscribe` is L4); the buy CTA is a placeholder href/route that L4
   turns into a real Lemon checkout. No accounts/auth, no adapters, no DB.
   ([ADR-0002](../adr/0002-layered-architecture-with-repository-ports.md), [ADR-0004](../adr/0004-no-user-accounts.md))
8. **Allowed new deps:** none required (the stack + Radix from L1 is sufficient). No
   MUI/shadcn, no icon/animation kits — flag if a dep is genuinely needed.

## Out of scope (deferred)

- Wiring `EmailCaptureForm` → `/api/subscribe`, `SubscribeController`/`Service`,
  the Lemon checkout creation, the webhook, analytics events
  (`email_signup`, `checkout_started`) → **L4**. L3 ships markup + client validation
  only; the buy CTA is a placeholder href until L4.
- Legal pages (`/terms`, `/privacy`, `/refund-policy`) → **L4**.
- Any database / persistence, controllers, services, adapters → **L4**.
- The deck itself (`/deck`) → already built in **L2**; L3 only links to it and reuses
  its diagram components.
- `/watch`, `VideoAdapter`, Cal.com, member area → **L6**.

## Public APIs

// content/offers.ts

`@/components/sections`, content via `@/content`.

## Architecture by concern

- **Typed content drives copy (content-model.md):** `offers.ts` / `faq.ts` /
  `testimonials.ts` hold all editorial data; section components read from them so copy
  changes never touch component code. `offers.ts` is typed `Offer[]`; the founding /
  launch prices live there (tunable until L4).
- **Section composition (ADR-0005, ADR-0002):** each section is a composite organism
  reusing L1 components + L2 diagrams — `Hero` (promise + the "270 files / 59 min"
  `Stat` metric + dual `CTAButtonGroup`), `TheShift` (the deck thesis, reusing
  `LLMDiagram`/`HarnessFrame`), `DeckPreview` (links to `/deck`), `WhatsInTheKit`,
  `Proof` (`Stat` metrics + `TestimonialCard`s), `Pricing` (`PricingTier` from
  `offers.ts` + 30-day guarantee note), `FAQ` (L1 Radix `Accordion` of `faq.ts`),
  `FinalCTA` (closing dual CTA + `EmailCaptureForm`). No new atoms; no pure
  pass-through wrappers. Token-only (the ESLint rule applies to `src/components/**`).
- **Page assembly:** `src/app/page.tsx` slots the sections, in SPEC §3 order, as
  children of the L1 `MarketingPageTemplate` (Navbar + sections + Footer). The Navbar
  carries the **persistent "Get the Kit" CTA** (buy placeholder href until L4).
- **SEO + OG (cross-cutting):** `src/app/layout.tsx` exports Next.js `metadata`
  (title, description, `openGraph`, `twitter`); `src/app/opengraph-image.tsx` is the
  `/` OG card and the per-route OG convention extends to `/deck` (and L4 legal pages).
- **No server in L3:** `EmailCaptureForm` is client validation only (no POST — L4);
  the buy CTA href is a placeholder route until L4 wires the Lemon checkout. No
  controllers/services/adapters/DB.
- **Verification:** no test framework, no CI. The driver runs `LEAN_GATE`
  (`pnpm install && pnpm build`) after every epic and `VERIFY_GATE`
  (`pnpm install && pnpm lint && pnpm exec tsc --noEmit && pnpm build`) on the last
  (nav+seo) epic. Final functional verification is **manual**: the user opens `/`
  and confirms the full anatomy renders, CTAs route, and SEO/OG are set.

## Per-epic specifications

Each epic is one fresh session = one commit, sized to the ~70k working-token
heuristic. The bd issue (`bd show <id>`) holds the full
CONTEXT/STEPS/ACCEPTANCE/HARD-RULES; this is the contract summary. The sections are
**split into two epics** (top-of-page narrative vs. bottom-of-page conversion) so a
single session does not have to build all nine sections.

### epic-0 — typed-content
Create `src/content/offers.ts` (the `Offer[]` catalog: Deck free, Harness Starter Kit
paid with founding $29 / launch $49 in cents; plus a `harnessStarterKit` reference),
`src/content/faq.ts` (typed FAQ entries — help-don't-sell answers using glossary
terms), `src/content/testimonials.ts` (named tester entries). EXTEND
`src/content/index.ts` to export them. Ground all copy in CONTEXT.md + SPEC §1/§3.
**Commit:** `l3 epic-0 typed-content: offers, faq, testimonials`

### epic-1 — sections-top  (Hero → Problem → The Shift → Deck preview → What's in the Kit)
Build the top-of-page narrative sections under `src/components/sections/`: `Hero`
(promise + "270 files / 59 min" `Stat` metric + dual CTA: read deck / get Kit),
`Problem` (babysitting AI), `TheShift` (agents = a harness, the deck thesis — reuse
`LLMDiagram`/`HarnessFrame`), `DeckPreview` (free-Deck preview + CTA to `/deck`),
`WhatsInTheKit` (the Harness Starter Kit contents). Compose L1 organisms + L2
diagrams, read from typed content, token-only. Barrel-export.
**Commit:** `l3 epic-1 sections-top: hero, problem, the-shift, deck-preview, whats-in-the-kit`

### epic-2 — sections-bottom  (Proof → Pricing → FAQ → Final CTA)
Build the conversion sections: `Proof` (authority + metrics via `Stat` +
`TestimonialCard`s from `testimonials.ts`), `Pricing` (founding $29→$49 via
`PricingTier` from `offers.ts` + 30-day guarantee note), `FAQ` (L1 Radix `Accordion`
rendering `faq.ts`), `FinalCTA` (closing dual CTA + `EmailCaptureForm`). Token-only,
read from typed content. EXTEND the sections barrel.
**Commit:** `l3 epic-2 sections-bottom: proof, pricing, faq, final-cta`

### epic-3 — nav+seo  (final epic — carries the gate)
Assemble `src/app/page.tsx`: slot all nine sections (SPEC §3 order) into the L1
`MarketingPageTemplate`; the Navbar carries the **persistent "Get the Kit" CTA**
(buy placeholder href until L4) and the Footer is wired. Add SEO metadata in
`src/app/layout.tsx` (title/description/`openGraph`/`twitter`) and the `/` OG card
(`src/app/opengraph-image.tsx`), plus per-route OG for `/deck` if not already present.
As the last epic this is where the driver runs the full **lint + typecheck + build**
gate (`VERIFY_GATE`). No separate verify epic; **final functional verification is
manual** — the user opens `/` (see checklist).
**Commit:** `l3 epic-3 nav+seo: assemble / page, persistent buy cta, seo metadata + og cards`

## Verification checklist (final — automated gate + manual review)

Automated portion runs as the driver's gate on the nav+seo epic; the `/` render +
CTA + SEO checks are performed manually by the user.

- [ ] `pnpm install` resolves; lockfile committed (no unexpected new deps).
- [ ] `pnpm lint` passes — **no raw design literals** anywhere in `src/components/**`.
- [ ] `pnpm exec tsc --noEmit` passes (TS strict, no errors, no `any`).
- [ ] `pnpm build` succeeds (Next.js 16 production build).
- [ ] `src/content/{offers,faq,testimonials}.ts` exist and are exported via the barrel;
      `offers.ts` is typed `Offer[]` and carries the founding/launch prices.
- [ ] `/` renders the full SPEC §3 anatomy in order: Hero → Problem → The Shift →
      Free Deck preview → What's in the Kit → Proof → Pricing → FAQ → Final CTA.
- [ ] Sections read from typed content (no copy hard-coded in components).
- [ ] Sections reuse L1 organisms + L2 diagrams (LLMDiagram/HarnessFrame/etc.) — no
      new atoms.
- [ ] The persistent header "Get the Kit" CTA is present; CTAs route to `/deck` and to
      the buy target (placeholder until L4); FAQ is a keyboard-operable Radix accordion.
- [ ] SEO metadata set in `layout.tsx`; `/` (and `/deck`) OG cards render.
- [ ] `EmailCaptureForm` in Final CTA is client-validation-only (no POST — wired in L4).
- [ ] `.beads/`, `.claude/`, `AGENTS.md`, `CLAUDE.md`, `src/types/*`, `src/styles/*`,
      `eslint.config.mjs`, the L1/L2 components are untouched.

## Risk register

| Risk | Impact | Mitigation |
|---|---|---|
| **Nine sections is a lot of composition** | budget overrun | Split into top-of-page narrative (epic-1, 5 sections) + bottom-of-page conversion (epic-2, 4 sections); sections only compose existing L1/L2 components + read typed content, so each is light. |
| Copy drifts from the glossary / help-don't-sell voice | off-brand page | Ground every section in CONTEXT.md + SPEC §1/§3; copy lives in typed content (epic-0) reviewed first. |
| A section hard-codes copy instead of reading typed content | content not editable without code | epic-0 builds the typed content first; sections (epics 1-2) read from `@/content`; the checklist greps for it. |
| `LEAN_GATE` runs `pnpm build` after every epic; a section importing a not-yet-built piece halts the loop | loop halts mid-phase | Typed content first (epic-0); sections only import already-built L1/L2 components; `/` is assembled only in the final epic. |
| Pricing numbers wrong / not tunable | mispriced launch | Prices live in `offers.ts` (cents), flagged tunable until L4; the page reads them, never hard-codes. |
| Accidentally wiring a server POST or real checkout | scope creep into L4 | HARD RULE: EmailCaptureForm is client-validation-only; the buy CTA is a placeholder href until L4. |
| no-hard-coded-values rule flags a section literal | lint red on VERIFY_GATE | Sections are under `src/components/**` and obey the rule; express all values via tokens/utilities. |
| bd hooks auto-commit `.beads/` | noise, not failure | Expected and tolerated per the task brief. |
