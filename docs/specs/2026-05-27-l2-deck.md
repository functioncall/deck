# L2 Deck — Spec

> Frozen execution spec for the **L2 Deck** Ralph loop (7 epics). Grounds in
> [docs/SPEC.md](../SPEC.md) (§2 architecture, §3 IA, §4 flows, §5 L2), the five
> [ADRs](../adr/) — esp. [ADR-0001](../adr/0001-componentize-the-deck.md)
> (componentize the deck, do not embed) — [agent_docs/deck-player.md](../../agent_docs/deck-player.md)
> (authoritative for the deck-player plan), [agent_docs/design-system.md](../../agent_docs/design-system.md),
> and [CONTEXT.md](../../CONTEXT.md). Once the loop runs this spec is read-only.
> There is no separate verify epic: the full build/lint/typecheck gate runs on the
> last epic (deck-assembly), and final functional verification is **manual** — the
> user opens `/deck` on desktop + mobile and confirms parity with `index.html`,
> then confirms the email capture + buy CTAs render.

## Context

BeyondTheLoop is a Next.js brand + pre-sell site (see SPEC §1). L0 laid the
foundation (Next.js 16 / TS strict / Tailwind 4 / pnpm, the layered skeleton, the
deck design tokens extracted verbatim into the Tailwind `@theme`, the
no-hard-coded-values ESLint rule, agent docs, `/styleguide`). L1 built the bespoke
design system — atoms (`Heading`, `Text`, `Label`, `Link`, `Badge`, `Button`,
`Input`, `CodeBlock`, `Callout`, `Stat`), molecules (`FieldRow`, `PricingTier`,
`FAQItem`, `TestimonialCard`, `EmailCaptureForm`, `CTAButtonGroup`), organisms
(`Navbar`, `Footer`, `Hero`, Radix `Dialog`, Radix `Accordion`) and
`MarketingPageTemplate` — all token-only, rendered in `/styleguide`.

L2 builds the **Deck only** — the free, interactive presentation ("the map"), the
trust-engine for the paid offers. The existing deck is a single 1.28 MB
self-contained `index.html` (88 slides across 8 sections, bespoke vanilla
HTML/CSS/JS, a per-slide multi-state progressive-reveal mechanic, keyboard/click
nav, a progress bar + slide counter). Per [ADR-0001](../adr/0001-componentize-the-deck.md)
we **rebuild it as a React slide-player that reuses the L1 atoms and tokens** and
**extract its diagrams as reusable components** (LLMDiagram, ContextWindow,
HarnessFrame, Gantt, plus Stat/Callout/CodeBlock atoms already in L1) — because
those diagrams are also the best marketing visuals and L3 reuses them. We do **not**
embed `index.html` as an iframe/black-box. `index.html` is the **read-only visual
source of truth** throughout L2 and is **deleted only in the final epic, after
`/deck` parity is confirmed** on desktop + mobile.

**Done when:** `pnpm install && pnpm lint && pnpm exec tsc --noEmit && pnpm build`
is green; `/deck` renders all 88 slides as React components matching `index.html`
on desktop + mobile (keyboard/click/swipe nav, progress bar, counter, jump menu,
the multi-state reveal mechanic, SSG/crawlable); the end-of-deck soft email capture
+ sticky bar + CTAs (back to `/`, buy the Kit) render; and `index.html` is deleted.

## Locked decisions

1. **Componentize the deck, do not embed** — rebuild as a React slide-player that
   reuses L1 atoms + L0 tokens; extract the deck's diagrams as reusable components.
   `index.html` stays read-only as the visual source of truth and is deleted in the
   **final epic only**, after parity. ([ADR-0001](../adr/0001-componentize-the-deck.md))
2. **Reuse L1 components, do not rebuild atoms** — slides and diagrams compose the
   existing `Heading`/`Text`/`Label`/`Badge`/`Button`/`CodeBlock`/`Callout`/`Stat`
   atoms and `Link`. New deck-specific pieces (slide-player engine, diagram
   components, slide components) live under `src/components/` (deck-player +
   diagrams) and `src/app/deck/`. ([ADR-0005](../adr/0005-bespoke-atoms-with-radix.md))
3. **Tokens only — no hard-coded design values** — every color/size resolves to a
   Tailwind utility from the L0 `@theme` (incl. `--color-layer-agent` /
   `--color-layer-harness` for the diagrams); the no-hard-coded-values ESLint rule
   (scoped to `src/components/**`) is the enforcement. Where the deck uses a one-off
   `clamp()` / breakpoint value that has no token, add a token to `src/styles/theme.css`
   — never an inline literal in a component. ([ADR-0005](../adr/0005-bespoke-atoms-with-radix.md))
4. **SSG + crawlable** — `/deck` is statically generated (all slides server-rendered
   into the HTML, progressively enhanced by the client nav layer) so it is shareable
   and crawlable. The reveal/nav interactions are `'use client'`; the slide content
   is server-rendered.
5. **Responsive, reuse the 768px breakpoint** — the deck's existing `max-width:768px`
   breakpoint is preserved (as a token/utility); touch swipe nav on mobile.
6. **Soft email capture only (no POST in L2)** — the end-of-deck capture reuses the
   L1 `EmailCaptureForm` (markup + client validation; submit is a no-op / `onSubmit`
   stub). Wiring to `/api/subscribe` is **L4**. No accounts/auth. ([ADR-0004](../adr/0004-no-user-accounts.md))
7. **No server code, no adapters, no DB, no new API routes** in L2 — this is the
   presentation layer for the deck only. ([ADR-0002](../adr/0002-layered-architecture-with-repository-ports.md))
8. **Allowed new deps:** none required beyond the existing stack; a lightweight
   swipe handler may be hand-rolled with pointer/touch events (no new gesture
   library) — flag if a dep is genuinely needed. No MUI/shadcn.

// components/deck-player/Stepper.tsx

// components/deck-player/ProgressBar.tsx
type ProgressBarProps = { current: number; total: number };

// components/deck-player/JumpMenu.tsx
type JumpMenuProps = { sections: DeckSection[]; onJump: (slideIndex: number) => void };

// components/deck-player/Reveal.tsx  — wraps a child shown at state >= frameMin
type RevealProps = { frameMin: number; mode?: 'frame' | 'label'; children: React.ReactNode; className?: string };

// components/diagrams/*  — each diagram composes L1 atoms + Reveal, token-only

via `@/components/deck-player`, `@/components/diagrams`, and `@/content/deck`.

## Architecture by concern

- **State machine (the reveal mechanic):** `SlidePlayer` owns
  `{ slideIndex, slideState }`. ArrowRight/Space/PageDown: if `slideState < maxState`
  for the current slide, increment state; else advance `slideIndex` (reset state).
  ArrowLeft/PageUp reverses symmetrically. Home/End jump to first/last slide. The
  `Reveal` primitive renders its child with a `frame-revealed`-equivalent token class
  when `slideState >= frameMin` (the React port of `data-frame-min` toggling). This
  mirrors `index.html`'s `setSlideState`; **do not invent a different mechanic**.
- **SSG + progressive enhancement:** `/deck` (`src/app/deck/page.tsx`) statically
  renders the full ordered slide list (server components) into the HTML for
  crawlability; `SlidePlayer` (`'use client'`) wraps them and adds nav/state. Each
  slide component renders its content server-side; only the player shell and `Reveal`
  are client.
- **Diagrams reuse L1 + tokens:** diagram components compose `Stat`/`Callout`/
  `CodeBlock` and token utilities (incl. `--color-layer-agent` / `--color-layer-harness`)
  — zero raw hex/px. They accept a `progressive`/`Reveal` integration so the same
  diagram renders both inside a stepped slide (deck) and statically (landing, L3).
- **Layering (ADR-0002):** deck-player + diagrams are components; slides compose
  diagrams + L1 atoms; `/deck` composes the slide registry into `SlidePlayer`. No
  pure pass-through wrappers; no server/controller/service/adapter code in L2.
- **Responsive:** the 768px breakpoint is preserved as a token/utility; mobile uses
  touch swipe (hand-rolled pointer/touch handlers) and a tap-to-advance affordance;
  the jump menu and counter stay reachable on mobile.
- **End-of-deck capture + CTAs (SPEC §3):** the final slide(s) render the L1
  `EmailCaptureForm` ("follow along") + a sticky capture bar + `CTAButtonGroup`
  linking back to `/` and to buy (placeholder buy href → real Lemon checkout in L4).
- **OG image:** `src/app/deck/opengraph-image.tsx` produces the `/deck` share image
  (Next.js OG image route), token-styled.
- **Verification:** no test framework, no CI. The driver runs `LEAN_GATE`
  (`pnpm install && pnpm build`) after every epic and `VERIFY_GATE`
  (`pnpm install && pnpm lint && pnpm exec tsc --noEmit && pnpm build`) on the last
  (deck-assembly) epic. Final functional verification is **manual**: the user opens
  `/deck` on desktop + mobile and confirms parity with `index.html` before accepting
  the `index.html` deletion.

## Per-epic specifications

Each epic is one fresh session = one commit, sized to the ~70k working-token
heuristic. The bd issue (`bd show <id>`) holds the full
CONTEXT/STEPS/ACCEPTANCE/HARD-RULES; this is the contract summary. The slide port
is **batched by section pair** (§0–1 / §2–3 / §4–5 / §6–7) so no single session has
to port too much slide content; the engine and diagrams are built first because
every slide depends on them.

### epic-0 — deck-engine
Build the React slide-player under `src/components/deck-player/`: `SlidePlayer`
(client; owns `{slideIndex, slideState}`; keyboard arrows/space/PageUp/PageDown/Home/End;
click + touch-swipe nav), `Slide` (anchor/stepper variants), `Stepper` (state dots),
`ProgressBar` (bar + `current/total` counter), `JumpMenu` (section jump), and the
`Reveal` primitive (the `data-frame-min` progressive-reveal port). SSG-friendly
(content stays server-rendered; only the shell is `'use client'`). Reuse the 768px
breakpoint. Barrel-export everything. A throwaway demo of a few placeholder slides
keeps the build green (real slides land in later epics).
**Commit:** `l2 epic-0 deck-engine: react slide-player (nav, progress, jump, reveal)`

### epic-1 — diagram-atoms
Extract the deck's reusable visuals into `src/components/diagrams/` as token-only
components reusing L1 atoms: `LLMDiagram` (`.llm-*`), `ContextWindow`
(`.context-window-large`), `HarnessFrame` (`.harness-*`/`.agent-frame`, integrates
`Reveal` for the progressive build), `Gantt` (`.gantt-*`). Reuse the L1 `Stat`,
`Callout`, `CodeBlock` atoms; use `--color-layer-agent`/`--color-layer-harness`
tokens. Render them in `/styleguide` (or a deck-diagrams section of it) so they have
a render home and the gate exercises them. Barrel-export.
**Commit:** `l2 epic-1 diagram-atoms: llmdiagram, contextwindow, harnessframe, gantt`

### epic-2 — slides-0-1  (§0 intro/title + §1 the problem)
Port the §0 and §1 slides from `index.html` into React slide components under
`src/app/deck/slides/`, composing the deck-engine + diagrams + L1 atoms, token-only.
Create `src/content/deck/sections.ts` (the 8-section metadata) and start the ordered
`slides/index.ts` registry (§0–1 entries with `maxState`). Match the original's
copy, stepper states, and layout. `index.html` is read-only reference.
**Commit:** `l2 epic-2 slides-0-1: intro + the-problem sections ported`

### epic-3 — slides-2-3  (§2 the shift + §3 the harness)
Port the §2 and §3 slides (the heaviest visual sections — harness frames + LLM
diagrams) into React slide components, reusing the diagrams from epic-1 and the
`Reveal` stepper states. Extend the `slides/index.ts` registry with §2–3 entries.
Token-only, parity with `index.html`.
**Commit:** `l2 epic-3 slides-2-3: the-shift + the-harness sections ported`

### epic-4 — slides-4-5  (§4 the mechanics + §5 proof/metrics)
Port the §4 and §5 slides (mechanics + the proof/metrics — Gantt, Stats, the
"270 files / 59 min / exit 0" metrics) into React slide components, reusing `Gantt`
+ `Stat`. Extend the registry with §4–5 entries. Token-only, parity.
**Commit:** `l2 epic-4 slides-4-5: the-mechanics + proof-metrics sections ported`

### epic-5 — slides-6-7  (§6 the kit/offer + §7 close/CTA)
Port the §6 and §7 slides (the Harness Starter Kit framing + the close) into React
slide components. Extend the registry with §6–7 entries so the full 88-slide order is
complete. Token-only, parity. (The end-of-deck capture + sticky bar + buy CTAs are
wired in the assembly epic.)
**Commit:** `l2 epic-5 slides-6-7: the-kit + close sections ported`

### epic-6 — deck-assembly  (final epic — carries the gate)
Wire `src/app/deck/page.tsx` (`/deck`, SSG) to assemble the complete ordered slide
registry into `SlidePlayer`; add the end-of-deck soft `EmailCaptureForm` (L1, client
validation, no POST) + a sticky email-capture bar + `CTAButtonGroup` linking back to
`/` and to buy (placeholder buy href, real checkout in L4); add the `/deck` OG share
image (`opengraph-image.tsx`). **Delete `index.html`** now that `/deck` reaches
parity (the deletion is part of this commit). As the last epic this is where the
driver runs the full **lint + typecheck + build** gate (`VERIFY_GATE`). No separate
verify epic; **final functional verification is manual** — the user opens `/deck` on
desktop + mobile (see checklist).
**Commit:** `l2 epic-6 deck-assembly: /deck route, end CTA + capture, og image, delete index.html`

## Verification checklist (final — automated gate + manual review)

Automated portion runs as the driver's gate on the deck-assembly epic; the `/deck`
render + interaction + parity checks are performed manually by the user.

- [ ] `pnpm install` resolves; lockfile committed (no unexpected new deps).
- [ ] `pnpm lint` passes — **no raw design literals** (no hex / `rgb`-`rgba`-`hsl` /
      `px`-`rem`-`em`) anywhere in `src/components/**`.

- [ ] `pnpm build` succeeds (Next.js 16 production build); `/deck` is statically
      generated (SSG) and crawlable.
- [ ] `/deck` renders all 88 slides as React components in the original order.
- [ ] Keyboard (arrows/space/PageUp/PageDown/Home/End), click, and touch-swipe nav
      all work; progress bar + `current/total` counter update; jump menu navigates.
- [ ] The per-slide multi-state reveal mechanic matches `index.html` (stepper dots +
      progressive frame/label reveal via the `Reveal` primitive).
- [ ] Diagrams (LLMDiagram, ContextWindow, HarnessFrame, Gantt) render token-only and
      match the original; they reuse the L1 Stat/Callout/CodeBlock atoms.
- [ ] End-of-deck soft `EmailCaptureForm` + sticky bar + CTAs (back to `/`, buy)
      render; the form is client-validation-only (no POST — wired in L4).
- [ ] `/deck` OG share image renders.
- [ ] `/deck` is responsive at the 768px breakpoint on mobile (desktop + mobile parity).
- [ ] `index.html` is **deleted** (only after parity is confirmed).
- [ ] `.beads/`, `.claude/`, `AGENTS.md`, `CLAUDE.md`, `src/types/*`,
